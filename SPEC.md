# Agentic Axtell Model — Julia + Lean Specification

## 1. Objective

Build a formally specified agent-based model of endogenous firm formation that extends Robert Axtell's firm-size model with agentic-AI capabilities, while preserving the original Axtell model as an exact sub-model recoverable by feature flags.

The implementation must exist in two forms:

1. **Julia** — executable reference implementation, simulation engine, diagnostics, enumeration of finite state spaces, empirical stationary distributions, and numerical experiments.
2. **Lean 4** — formal specification and proof layer for state invariants, exact baseline recovery, finite-state properties, Markov structure, and convergence results.

The two implementations must encode the same mathematical transition system.

The project must **not use Agents.jl** or any other agent-based modeling framework.

---

## 2. Core Design Principle

The canonical object is a deterministic transition function driven by an explicit random draw:

\[
T_{\phi,\theta}: S \times \Omega \to S,
\]

where:

- \(S\) is the model state space,
- \(\Omega\) is the space of primitive random draws,
- \(\theta\) is the parameter vector,
- \(\phi\) is the feature-flag configuration.

Simulation is generated by

\[
X_{t+1}=T_{\phi,\theta}(X_t,\omega_t),
\]

with draws

\[
\omega_t \sim Q_{\phi,\theta}(\cdot\mid X_t).
\]

The induced Markov kernel is

\[
P_{\phi,\theta}(x,B)
=
\Pr\left[T_{\phi,\theta}(x,\omega)\in B\right].
\]

The deterministic transition map and the random-draw distribution must be implemented separately.

This separation is mandatory.

---

## 3. Exact Axtell Nesting Requirement

Let \(\phi_A\) denote the configuration in which all agentic extensions are disabled.

The extended model must satisfy the pathwise identity

\[
\boxed{
T_{\phi_A,\theta_A}(x,\omega)
=
T_A(x,\omega)
}
\]

for every admissible baseline state \(x\) and every admissible primitive random draw \(\omega\).

This is stronger than equality in distribution and is the primary architectural invariant.

Consequently, for a common initial state and common random-number stream,

\[
X_t^{\mathrm{extended}}
=
X_t^{\mathrm{Axtell}}
\qquad \forall t.
\]

### Required feature flags

At minimum:

```text
allow_compute
allow_spawn
allow_termination
allow_delegation
allow_specialization
allow_hierarchy
allow_compute_market
allow_compute_inheritance
allow_agent_mutation
```

The baseline configuration must set every extension flag to `false`.

Feature flags must alter admissible actions or activate explicit extension operators. Do not simulate disabled features by assigning very large costs or near-zero probabilities.

---

## 4. Model Layering

The implementation should be organized as nested layers.

### Layer 0 — Axtell baseline

Fixed population, effort choice, firm membership, firm formation, worker movement, production, compensation, and the original behavioral update logic.

### Layer 1 — Compute

Agents may possess and allocate compute resources.

### Layer 2 — Endogenous population

Agents may spend resources to spawn or terminate agents.

### Layer 3 — Endogenous organization

Delegation, hierarchy, specialization, supervision, or related organizational structures.

### Layer 4 — Compute economy

Potential future extension: compute markets, compute ownership, prices, capital accumulation, data centers, or other resource-allocation institutions.

Each layer must augment the previous layer rather than rewrite it.

## 5. State Representation

The extended state should conceptually decompose as

\[
X_t=(X_t^A,X_t^{AI}).
\]

### Baseline state

At minimum, each baseline agent contains fields corresponding to

\[
(\theta_i,e_i,f_i),
\]

where:

- \(\theta_i\): agent heterogeneity required by the Axtell specification,
- \(e_i\): effort,
- \(f_i\): firm membership.

### Agentic extension state

Potential fields include

\[
(C_i,p_i,\tau_i,\ldots),
\]

where:

- \(C_i\): compute budget or allocation,
- \(p_i\): parent / creator identifier,
- \(\tau_i\): specialization or agent type.

### Distinct graph objects

Firm membership and delegation/lineage must be represented separately.

Firm organization:

\[
\mathcal F_t=\{F_1,\dots,F_K\}.
\]

Lineage graph:

\[
G_t^L=(V_t,E_t^L).
\]

Future active-delegation graph:

\[
G_t^D=(V_t,E_t^D).
\]

Do not assume that creator, manager, and firm membership are the same relation.

---

## 6. Action Sets

Let the baseline action set be

\[
\mathcal A_i^A.
\]

This includes only actions present in the Axtell model, such as effort adjustment, firm switching, and firm creation as dictated by the exact baseline specification.

The extended action set is

\[
\mathcal A_i
=
\mathcal A_i^A
\cup
\mathcal A_i^{AI}.
\]

Potential extension actions include:

```text
spawn
terminate
delegate
allocate_compute
change_specialization
```

When a capability flag is disabled, the corresponding action must be absent from the admissible action set.

Example:

\[
\texttt{allow\_spawn}=\texttt{false}
\implies
\text{spawn}\notin\mathcal A_i.
\]

---

## 7. Compute Must Initially Remain Separate From Effort

Do not reinterpret the original Axtell effort variable as compute.

Keep baseline effort \(e_i\) unchanged and introduce compute \(c_i\) as a new variable.

A generic production representation is

\[
Y_f
=
F_A(\{e_i\}_{i\in f};\theta_A)
+
\Delta F_{AI}(\{e_i\},\{c_i\},G_f;\psi).
\]

The recovery condition is

\[
\texttt{allow\_compute}=\texttt{false}
\implies
\Delta F_{AI}=0.
\]

Likewise, utility should decompose as

\[
U_i=U_i^A+\Delta U_i^{AI},
\]

with

\[
\Delta U_i^{AI}=0
\]

whenever all relevant extension flags are disabled.

---

## 8. Spawning

Spawning changes the agent population and must be distinguished from baseline firm creation.

Baseline firm creation changes the number of firms but not the number of agents.

Spawning changes the number of agents:

\[
N_{t+1}=N_t+B_t-D_t.
\]

For the first extension, use a bounded population:

\[
N_t\leq N_{\max}.
\]

A minimal spawn operation may take

\[
(i,C_i)
\mapsto
(i,C_i-\kappa-c_j)+(j,c_j),
\]

subject to feasibility constraints.

The new child should enter the baseline Axtell environment as an ordinary agent with baseline fields such as

\[
(e_j,f_j,\theta_j).
\]

### Initial inheritance rule

Use the simplest rule first:

\[
\theta_j=\theta_i.
\]

Mutation or specialization should be separate extensions.

### TODO

Specify:

- exact spawn cost \(\kappa\),
- compute transfer rule,
- initial effort of child,
- initial firm membership of child,
- whether parent and child must initially share a firm,
- behavior when \(N=N_{\max}\).

## 9. Randomness

Randomness must not be hidden inside the deterministic transition function.

Define an explicit random-draw object containing all primitive randomness needed for one model update.

Potential fields:

```text
selected_agent
candidate_action
candidate_firm
candidate_effort
tie_break_draw
spawn_child_seed
misc_uniforms
```

The exact representation may change, but a supplied draw must fully determine the next state.

### Julia requirement

Conceptual API:

```julia
sample_draw(rng, state, config, params) -> Draw
step(state, draw, config, params) -> State
```

### Lean requirement

Conceptual API:

```lean
def step : Config → Params → State → Draw → State
```

Probability can be layered on after deterministic semantics are established.

## 11. Lean Architecture

Use Lean 4 with mathlib.

Prioritize semantic clarity over premature abstraction.

The first Lean implementation should model a finite version of the economy so that:

- equality is decidable,
- the state space is finite,
- admissibility predicates are explicit,
- finite sums and transition probabilities are tractable.

## 12. Finite Approximation

The first theorem-bearing model should use finite bounds.

At minimum:

\[
N\leq N_{\max},
\]

\[
e_i\in\mathcal E,
\]

\[
c_i\in\mathcal C,
\]

with finite sets \(\mathcal E\) and \(\mathcal C\).

Firm identifiers and agent identifiers must also live in finite types or bounded domains.

This should make the global state space finite.

The finite approximation is not merely an implementation convenience; it is the first mathematical model for which convergence will be proved.

---

## 13. Required Invariants

At minimum, encode and test/prove the following.

### Baseline invariants

- Every active agent belongs to exactly one valid firm.
- Every firm contains only active agents.
- Baseline effort lies in the allowed effort set.
- Baseline state remains valid after every baseline transition.

### Compute invariants

When compute is enabled:

- compute allocations are nonnegative,
- total allocated compute obeys the specified resource constraint,
- spawning cannot create compute unless the model configuration explicitly permits external compute acquisition.

### Population invariants

- active-agent count never exceeds \(N_{\max}\),
- active IDs are unique,
- terminated IDs are not treated as active agents,
- child creation preserves validity.

### Graph invariants

When lineage is enabled:

- every child has at most one creator,
- creator IDs exist at creation time,
- lineage relations satisfy whatever acyclicity assumptions are chosen.

### Feature isolation

If a feature is disabled, its state variables must have no behavioral effect on baseline transitions.

## 14. Theorem Roadmap

### Theorem 1 — Transition well-definedness

For every valid state, admissible configuration, parameter vector, and admissible draw, `step` returns a valid state.

Formally:

\[
\operatorname{Valid}(x)
\land
\operatorname{Admissible}(\omega,x)
\implies
\operatorname{Valid}(T(x,\omega)).
\]

### Theorem 2 — Exact Axtell recovery

For baseline flags:

\[
\boxed{
T_{\phi_A,\theta_A}(x,\omega)
=
T_A(x,\omega)
}
\]

for all valid baseline states and admissible draws.

### Theorem 3 — Pathwise equivalence

Given the same initial state and random draw sequence:

\[
X_t^{\mathrm{extended}}
=
X_t^{A}
\qquad \forall t.
\]

This should follow by induction from Theorem 2.

### Theorem 4 — Finite state space

Under finite bounds on population, effort, compute, firm IDs, and any enabled graph representation, the set of valid global states is finite.

### Theorem 5 — Markov property

For i.i.d. or state-conditioned primitive draws whose distribution depends only on the current state and parameters, the induced stochastic process is Markov.

### Theorem 6 — Stationary distribution existence

For the finite-state model, establish existence of at least one stationary distribution.

### Theorem 7 — Unique stationary distribution under sufficient conditions

Identify explicit model conditions implying irreducibility.

Establish aperiodicity, potentially through a positive-probability self-loop or another sufficient condition.

Then prove uniqueness of \(\pi\).

### Theorem 8 — Convergence

Under irreducibility and aperiodicity:

\[
\boxed{
\|\mu P^t-\pi\|_{TV}\to0
}
\]

for every initial distribution \(\mu\).

### Future theorem — Removal of truncation

For a sequence of bounded models with stationary distributions \(\pi_K\), investigate conditions under which

\[
\pi_K\Rightarrow\pi
\]

as artificial state-space bounds are relaxed.

### Future theorem — Agentic reproduction threshold

Investigate whether a simplified spawning model admits a reproduction parameter \(R\) such that a result analogous to

\[
R<1 \implies \text{positive recurrence / population stability}
\]

can be proved without a hard population cap.

This is a research target, not an initial acceptance criterion.

## 15. Julia Validation Strategy

The Julia implementation should support both simulation and exhaustive analysis for small parameterizations.

Required capabilities:

1. Simulate trajectories from explicit seeds.
2. Replay a trajectory from a recorded sequence of `Draw` objects.
3. Enumerate all valid states for sufficiently small finite models.
4. Enumerate all possible one-step transitions for small models.
5. Construct a transition matrix for small state spaces.
6. Numerically compute communicating classes.
7. Numerically test irreducibility and aperiodicity.
8. Compute stationary distributions numerically.
9. Compare empirical occupation measures to stationary probabilities.
10. Compare baseline and extended models pathwise with all extension flags disabled.

Do not rely on simulation alone when exact finite-state enumeration is feasible.

## 16. Cross-Language Consistency

Julia and Lean must not drift into different model definitions.

Use a single written specification for:

- state fields,
- validity predicates,
- feature flags,
- action admissibility,
- deterministic transition semantics,
- primitive random draws,
- parameter constraints.

For small deterministic fixtures, create test vectors of the form

```text
initial_state
config
params
draw
expected_next_state
```

and verify the Julia implementation against them.

Where practical, mirror the same fixtures in Lean examples or theorems.

Do not attempt automatic Julia-to-Lean code generation in the first implementation.

## 17. Initial Model Scope

The first implementation should contain only:

### Baseline

A finite-state version of the original Axtell model.

### Extension 1

Compute state, but no effect unless `allow_compute=true`.

### Extension 2

Spawning, enabled only when `allow_spawn=true`.

Do not initially implement:

- hierarchy,
- delegation,
- specialization,
- compute markets,
- mutation,
- complex inheritance,
- network communication costs,
- endogenous model selection,
- unbounded population growth.

Those features belong in later milestones.

## 19. Coding Rules

### Julia

- No Agents.jl.
- No hidden global RNG.
- No stochastic behavior inside `step`.
- Prefer concrete immutable structs for logical state.
- Mutation may be used internally for performance only when observational semantics remain identical.
- Keep model logic independent from plotting and data-analysis code.
- Avoid premature optimization.
- Add docstrings for all public functions.
- Add property tests where useful.

### Lean

- Keep definitions executable where reasonable.
- Separate data validity from transition behavior.
- Prefer small lemmas over monolithic proofs.
- Prove feature-isolation lemmas early.
- Avoid introducing measure theory until finite deterministic semantics and finite probability mass functions are stable.
- Use mathlib rather than recreating standard finite probability or Markov-chain machinery when suitable abstractions exist.

### Milestone 0 — Repository scaffold

Create Julia and Lean projects, module layout, CI hooks, and this specification.

### Milestone 1 — Baseline finite Axtell state

Implement state, parameters, actions, validity predicates, and deterministic baseline transition.

Deliverables:

- Julia baseline tests,

Introduce all feature flags, with all extensions initially inert.

### Milestone 4 — Spawning

Only after prior milestones pass:

- hierarchy,

- mutation,
- compute markets,

## 21. Acceptance Criteria

The first research-grade release is complete only if all of the following hold.

### Architecture

- Julia uses no ABM framework.
- `step` is deterministic conditional on an explicit draw.
- sampling and state transition are separate.
- feature flags are explicit.
- baseline and extension state are cleanly separated.

### Baseline recovery

- A Julia regression test verifies pathwise equality between baseline and extended code under baseline flags across many generated valid states and draw sequences.
- Lean contains a theorem proving exact one-step baseline recovery.
- Lean contains a pathwise finite-time recovery theorem derived by induction.

### State validity

- Julia tests enforce all listed invariants.
- Lean proves transition preservation of validity for the implemented finite model.

### Finite stochastic model

- Julia can enumerate a toy state space and construct its transition matrix.
- Row sums equal one to numerical tolerance.
- Julia can calculate a stationary distribution for the toy system.

### Convergence

- Lean formally states the finite-state convergence result used by the project.
- The model-specific assumptions required for the theorem are explicit.
- At least one nontrivial parameterization is shown to satisfy those assumptions, either formally or via a clearly separated finite verification strategy that can later be formalized.

### Reproducibility

- Fixed seeds reproduce identical Julia trajectories.
- Recorded draw streams reproduce trajectories without access to an RNG.
- Small transition fixtures are documented and shared across the Julia and Lean implementations.

## 22. Non-Goals for the First Version

Do not attempt to solve all research questions simultaneously.

The first version does not need to establish:

- Zipf's law analytically,
- empirical fit to U.S. firm-size data,
- unbounded-population recurrence,
- continuous effort convergence,
- continuous compute allocation,
- endogenous hierarchical organization,
- market equilibrium for compute,
- optimal control by agents,
- heterogeneous foundation models,
- realistic LLM inference economics.

The first objective is a correct nested model with an executable Julia implementation and a formally analyzable Lean representation.
